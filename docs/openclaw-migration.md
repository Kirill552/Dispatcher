# Миграция ИИ-Диспетчера на OpenClaw

## Зачем переходить

Текущий проект — 1800+ строк Python с кнопками, пошаговыми flow, ручным парсингом ответов клиента. Каждое изменение в логике сбора данных = переписывание кода.

OpenClaw убирает всю эту боль:

| Проблема сейчас | Решение в OpenClaw |
|-----------------|-------------------|
| Кнопки и пошаговый flow для сбора данных (500+ строк) | AI ведёт свободный диалог, сам извлекает данные из текста |
| Жёсткая последовательность — пропустил шаг = сломалось | Нет жёсткого flow — бот понимает контекст, уточняет что не хватает |
| Клиента не помнит между сессиями | MEMORY.md + memory-lancedb: «Иван Петрович, опять из Сарапула в Казань?» |
| Каждый диалог с нуля | Сессии + память: знает историю заказов, предпочтения |
| Sales agent — 200 строк Python (LAER + Re-CAP) | Инструкции в SKILL.md: «торгуйся до 25% минимум маржи» |
| Двухуровневая классификация — 300 строк | Не нужна — OpenClaw сам понимает intent |
| Sentiment Guard — 100 строк | Правило в AGENTS.md: «агрессия → передай владельцу» |
| Smart pricing — 200 строк | Плагин registerTool на 50 строк или инструкция в скилле |
| Мониторинг откликов — отдельный сервис | Plugin registerService — polling в фоне |
| Голосовые — нет | Встроенный Whisper: клиент надиктовал → бот понял |

**Было**: ~1800 строк Python + боль с кнопками
**Будет**: ~500 строк TypeScript (плагины) + ~150 строк Markdown (скиллы)

### Отдельный инстанс

Диспетчер работает на **отдельном** OpenClaw gateway (порт 18790), не на том же что новостной бот (18789). Причины:

1. **Разная память** — новостной бот помнит новости Сарапула, диспетчер помнит клиентов и грузы
2. **Разные модели** — диспетчеру может понадобиться модель поумнее для торговли
3. **Разная аудитория** — новости = подписчики, диспетчер = клиенты-заказчики
4. **Изоляция рисков** — баг в одном не ломает другого
5. **Разные Telegram боты** — у каждого свой токен

Оба процесса могут жить на одном VPS (85.208.85.104 или отдельный).

## Что становится чем

### 1. ATI.su API клиент → Plugin `ati-cargo`

Текущий `ati_integration/ati_client_v2.py` (400 строк Python) переписывается как OpenClaw plugin:

```
~/.openclaw/extensions/ati-cargo/index.ts
```

**Инструменты (registerTool):**

| Tool | Описание | Текущий аналог |
|------|----------|---------------|
| `ati_create_cargo` | Разместить груз на ATI.su | `create_cargo_request()` |
| `ati_check_responses` | Проверить отклики водителей | `get_cargo_responses()` |
| `ati_contact_carrier` | Написать перевозчику | Новое — через ATI мессенджер |
| `ati_get_cargo` | Получить данные груза | `get_cargo_by_id()` |
| `ati_city_search` | Автодополнение городов | `get_city_id()` |

**Фоновый сервис (registerService):**

| Service | Описание | Текущий аналог |
|---------|----------|---------------|
| `ati-monitor` | Polling откликов каждые 30 сек | `offers_monitor.py` |

Бот вызывает эти инструменты сам, когда нужно — по описанию в skill.

### 2. Сбор данных заказа → Skill `dispatcher-client`

Текущий `ai_dispatcher_logic.py` (500+ строк пошагового flow) заменяется на ~80 строк Markdown:

```
~/sarapul-bot/.agents/skills/dispatcher-client/SKILL.md
```

Skill описывает:
- **Что собирать**: откуда, куда, вес, тип кузова, дата загрузки, описание груза
- **Как собирать**: свободный диалог, уточняй что не хватает, предлагай «как в прошлый раз»
- **Ограничения**: только грузы от 200 кг, только межгород
- **Размещение**: когда всё собрано → `ati_create_cargo`
- **Отклики**: когда пришли → показать 3 лучших с наценкой 40%
- **Торговля**: до 3 раундов, минимум 25% маржи
- **Закрытие**: клиент согласился → уведомить Кирилла

### 3. Sales agent → Часть того же Skill

Текущий `sales_agent.py` (200 строк LAER + Re-CAP) — инструкция в 20 строк внутри skill:

```markdown
## Если клиент просит скидку
- Раунд 1: выслушай, признай обоснованность, уточни детали. Снизь на 5%.
- Раунд 2: переформулируй ценность, предложи компромисс. Снизь ещё на 5%.
- Раунд 3: «Это минимально возможная цена».
- Никогда не опускайся ниже 25% маржи от цены водителя.
- Если маржа на пределе → «Передаю менеджеру для обсуждения».
```

OpenClaw сам реализует эту логику в разговоре — не нужен код.

### 4. Двухуровневая классификация → Не нужна

Текущий `enhanced_classifier.py` (300 строк) существует потому что обычный бот не понимает intent. OpenClaw — LLM, он понимает «подумаю», «в целом неплохо», «мошенники» без кода.

Sentiment Guard → одна строка в AGENTS.md:
```
Если клиент агрессивен (оскорбления, угрозы суда) → немедленно передай владельцу (408001372).
```

### 5. Smart pricing → Инструкция или плагин

Два варианта:

**Вариант A** — инструкция в skill (бесплатно, достаточно для старта):
```markdown
Наценка 40% от цены водителя. Если пятница + срочно → 45%. Тяжёлый груз → 35%.
```

**Вариант B** — plugin `ati-pricing` с ML-моделью (когда будет 200+ сделок):
```typescript
api.registerTool({
  name: "calculate_price",
  handler: async ({ carrier_price, cargo_type, urgency }) => {
    // LightGBM предсказание на основе истории
  }
});
```

### 6. Мониторинг откликов → Plugin service

Текущий `offers_monitor.py` (150 строк) → registerService в плагине `ati-cargo`:

```typescript
api.registerService({
  name: "ati-offer-monitor",
  interval: 30000, // каждые 30 сек
  handler: async () => {
    // Проверить активные грузы → если есть отклики → уведомить через сессию
  }
});
```

### 7. База данных → OpenClaw memory

Текущая SQLite с таблицами Order, Client, MonitoringSession, CarrierContact → заменяется на:

| Данные | Где хранятся в OpenClaw |
|--------|------------------------|
| Информация о клиенте | MEMORY.md (автоматически) |
| История заказов | memory-lancedb (семантический поиск) |
| Текущий заказ | Сессия (эфемерно) |
| Активные грузы на ATI | JSON-файл, управляемый плагином |
| Настройки бизнеса | TOOLS.md |

Для сложной аналитики (конверсия, маржа за период) можно добавить plugin с SQLite — но для базового flow хватает memory.

### 8. Telegram бот → OpenClaw channel

Текущий `bot/client_bot.py` (200 строк python-telegram-bot) → не нужен. OpenClaw сам подключается к Telegram через встроенный канал.

### 9. Уведомления владельцу → Skill `dispatcher-admin`

```
~/sarapul-bot/.agents/skills/dispatcher-admin/SKILL.md
```

Когда клиент согласился на сделку → бот пишет Кириллу:
```
Новая сделка!
Груз: мебель 2000 кг
Маршрут: Сарапул → Казань
Цена клиенту: 70,000₽
Цена водителя: 50,000₽
Маржа: 20,000₽ (40%)
Водитель: ООО «Перевозки», рейтинг 4.8
Клиент: Иван Петрович, +7900123456
```

## Что даёт память OpenClaw

### Сценарий: постоянный клиент

**Сейчас (Python-бот):**
```
Клиент: Привет, нужно перевезти мебель
Бот: Здравствуйте! Давайте оформим заявку.
     Откуда отправка?
Клиент: Сарапул
Бот: Куда доставка?
Клиент: Казань
Бот: Вес груза?
... (ещё 5 вопросов по кнопкам)
```

**С OpenClaw:**
```
Клиент: Привет, опять мебель надо отправить
Бот: Привет, Иван Петрович! Опять из Сарапула в Казань, как в прошлый раз?
     Тент, примерно 2 тонны?
Клиент: Да, только в этот раз 3 тонны и в Ижевск
Бот: Понял — мебель, 3 тонны, Сарапул → Ижевск, тент.
     Когда забрать? В прошлый раз просили на понедельник.
Клиент: Да, на понедельник
Бот: Отлично, размещаю! Обычно отклики приходят за 15-30 минут.
```

3 сообщения вместо 8. Клиент чувствует что его помнят.

### Сценарий: голосовое сообщение

**Сейчас**: не поддерживается.

**С OpenClaw:**
```
Клиент: [голосовое] «Слушай, тут надо доски обрезные
         пять тонн из Воткинска в Набережные Челны,
         на среду если можно»

Бот: Записал! Доски обрезные, 5 тонн,
     Воткинск → Набережные Челны, среда.
     Какой кузов предпочитаете — тент или борт?
```

Whisper встроен в OpenClaw — ноль дополнительного кода.

## Флоу клиента (новый)

```
1. Клиент пишет в Telegram / MAX
   │
   ▼
2. OpenClaw получает сообщение
   │ Skill "dispatcher-client" активируется по описанию
   │ Если постоянный клиент → подгружает из памяти
   ▼
3. Свободный диалог: бот собирает данные
   │ Откуда, куда, что, вес, кузов, дата
   │ Уточняет что не хватает
   │ Для постоянных — «как в прошлый раз?»
   │ Голосовые → Whisper → текст автоматически
   ▼
4. Данные собраны → ati_create_cargo
   │ Plugin вызывает ATI.su API v2
   │ POST /v2/cargos → груз размещён
   │ Бот: «Ищу перевозчиков, 15-30 минут»
   ▼
5. ati-monitor (фоновый сервис) polling каждые 30 сек
   │ Есть отклики?
   │ Нет → ждём
   │ Да ↓
   ▼
6. Бот анализирует отклики
   │ Сортировка по цене + рейтинг
   │ Выбирает топ-3
   │ Через ati_contact_carrier уточняет готовность
   ▼
7. Бот идёт к клиенту с предложением
   │ Цены С НАЦЕНКОЙ 40% (клиент не видит реальную)
   │ «Есть 3 варианта: ...»
   │ Рыночный контекст: «средняя ставка по маршруту X-Y тысяч»
   ▼
8. Клиент выбирает / торгуется
   │ Согласен → шаг 9
   │ «Дорого» → торговля (до 3 раундов, минимум 25% маржи)
   │ Отказ → бот запоминает, прощается профессионально
   ▼
9. Сделка! Бот уведомляет Кирилла (408001372)
   │ Все детали: груз, маршрут, цена клиента, цена водителя, маржа
   │ Кирилл принимает оплату и оформляет сделку
   ▼
10. Бот запоминает клиента в MEMORY.md
    │ Имя, маршруты, предпочтения, история заказов
    │ Следующий раз — диалог быстрее
```

## Безопасность

| Мера | Зачем |
|------|-------|
| `exec.security: "deny"` | Клиенты не запустят команды |
| `gateway.bind: "loopback"` | Порт не торчит наружу |
| `auth.token` 256 бит | Защита от перехвата |
| `clawhub: disabled` | Нет вредоносных скиллов |
| Credentials в env vars | Бот не видит API ключи |
| Skill rules | Бот не говорит про ATI, наценку, ИИ |
| per-channel-peer | Клиенты не видят чужие заказы |

Финансы (оплата) остаются у Кирилла — бот к деньгам доступа не имеет.

## План реализации

### Фаза 1: MVP (1-2 дня)

1. Создать проект `~/dispatcher-bot/` на сервере
2. Написать Skill `dispatcher-client` — сбор заказа + предложение цены
3. Написать Skill `dispatcher-admin` — уведомления
4. Портировать `ati_client_v2.py` → Plugin `ati-cargo` (TypeScript)
5. Настроить openclaw.json + systemd service на порту 18790
6. Создать нового Telegram бота через BotFather
7. Тест: отправить заявку → груз на ATI → отклики → предложение клиенту

### Фаза 2: Полировка (3-5 дней)

1. Добавить мониторинг откликов (registerService, 30 сек polling)
2. Настроить SOUL.md — персона диспетчера (профессиональный, уверенный)
3. Добавить торговлю в skill (3 раунда, 25% минимум маржи)
4. Протестировать с реальными данными
5. Добавить MAX канал (если нужен)

### Фаза 3: Умные фичи (когда пойдут заказы)

1. ML pricing plugin (когда будет 200+ завершённых сделок)
2. RAG по истории сделок (memory-lancedb уже поддерживает)
3. Автогенерация документов (plugin с pdfkit)
4. Website Chat для приёма заявок с сайта
5. Обратка и консолидация маршрутов
6. Аналитика для владельца: «конверсия за неделю», «средняя маржа»
